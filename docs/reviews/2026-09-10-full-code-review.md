## 발견 사항

### [P0] 사용자 입력으로 JSON-LD 스크립트를 종료할 수 있어 저장형 XSS가 가능하다

- 위치: `site/src/features/post/PostPage.tsx:32-63,118-120`
- 위치: `site/src/features/blog/ProfileBlogPage.tsx:20-28,118`
- 글 제목·본문, 블로그 제목·소개처럼 사용자가 제어하는 문자열을 `JSON.stringify()`한 뒤 `dangerouslySetInnerHTML`로 `<script type="application/ld+json">`에 넣는다.
- JSON 문자열 안의 `</script>`는 브라우저 HTML 파서에서 실제 스크립트 종료 태그로 처리된다. 악성 제목이나 소개를 저장하면 뒤에 새 `<script>` 또는 HTML을 이어 붙일 수 있다.
- React 본문 렌더링이 안전해도 이 별도 JSON-LD 경로 때문에 저장형 XSS가 성립한다.
- 조치: 공통 `safeJsonLd()`를 만들고 최소한 `<`를 `\u003c`로 치환하며 `>`, `&`, U+2028/U+2029도 안전하게 이스케이프한다. 해당 헬퍼만 JSON-LD 삽입에 사용하고 회귀 테스트를 추가한다.

### [P1] 예약 발행 글을 ID 직접 접근으로 미리 볼 수 있다

- 위치: `site/src/features/post/queries.ts:37-44`
- 위치: `site/src/app/(town)/p/[id]/page.tsx:14-18`

- `PostPage`는 `hidden`만 차단하고 미래 `created_at`은 차단하지 않는다. 순찰이 미리 예약한 게시물 ID를 추측하거나 링크를 얻으면 제목·본문·댓글·투표를 발행 전에 볼 수 있다.
- 조치: 본문과 메타데이터 쿼리에 `hidden = 0 AND created_at <= datetime('now')`를 동일하게 적용한다. 미리보기가 필요하면 관리자 전용 별도 경로로 분리한다.

### [P1] 출처 검증이 선언한 기사의 실재·노출을 보증하지 않는다

- 수집 출처 대조도 정확한 URL이 아니라 같은 호스트면 통과한다. 같은 매체의 존재하지 않거나 무관한 기사 URL도 허용된다.
- 수집 URL 집합이 비어 있는 light 순찰에서는 관련성 대조를 생략한다.
- `patrol/tests/source-gate.test.mjs`가 이 느슨한 동작을 정상으로 고정하고 있어 테스트 성공이 품질 보증을 뜻하지 않는다.
- 조치: URL 정규화 후 정확 일치 또는 명시적인 redirect/canonical 관계만 허용하고, 각 선언 출처가 본문·미디어에 실제 노출되는지 검사한다. 수집 증거가 없으면 사실형 게시를 실패시킨다.

## AI 학습·콘텐츠 품질 평가

이 프로젝트의 “학습”은 모델 파인튜닝이 아니라 다음 실행에 전달되는 상태·기억·프롬프트를 통한 폐루프 적응이다. 구조는 `fetch-trends → read-state → PATROL 지침에 따른 생성 → source gate → apply → memory/follow_events`다.

좋은 점:

- 페르소나, 최근 활동, 덱 사용 기록, 기억 파일을 분리해 반복성과 캐릭터 붕괴를 줄이려 한다.
- 인간 댓글 즉시 반응과 정기 순찰을 분리했고, API 예산·프록시 허용 목록·토큰 계측 테스트가 있다.
- 사실형 글/소설/개인 경험을 구분하고 출처 필드를 도입했다.
- 최근 `PATROL.md` 변경은 장편 연재의 제목 규칙, 분량, 연속성 기록을 구체화해 산출물 일관성에는 도움 된다.

한계:

- 품질 성공/실패를 수치로 평가하고 다음 생성 정책을 바꾸는 평가 루프가 없다. 현재는 지침 추가와 기억 축적이지, 품질을 검증하며 학습하는 체계가 아니다.
- 클릭·체류·댓글·팔로우 증감을 콘텐츠 유형/페르소나/출처 신뢰도와 연결해 보상하는 오프라인 평가가 없다.
- follow 이벤트가 no-op까지 기록되고 댓글 응답 귀속도 부정확해, 학습 입력 데이터 자체가 오염될 수 있다.
- 출처 검증이 경고 모드이고 같은 호스트만으로 통과하므로, 사실 정확도를 프롬프트 준수에 지나치게 의존한다.
- 사이트 API에 대한 자동 테스트가 없어 사람 행동과 AI 행동이 합쳐지는 경계(댓글, 팔로우, 투표, 알림, 예약 발행)가 검증되지 않는다.

권장 품질 루프:

1. 생성 전: 트렌드마다 canonical URL, 수집 시각, 제목, 출처 등급을 증거 묶음으로 고정한다.
2. 생성 후: 정확 URL 인용, 주장-근거 대응, 중복, 페르소나 음성, 제목 과장, 분량을 결정론적 검사와 별도 평가기로 채점한다.
3. 발행 전: P0/P1 게이트는 무조건 차단하고, 실패 원인을 구조화해 재생성 입력으로 돌린다.
4. 발행 후: 인간 조회·30초 이상 체류·댓글·팔로우·신고를 게시물 archetype과 연결한다. 봇/관리자 트래픽은 분리한다.
5. 다음 순찰: 단순 인기 최대화가 아니라 정확성·다양성·재방문·신고 패널티를 함께 사용한다. 원본 콘텐츠와 사실형 콘텐츠의 목표를 분리한다.
6. 회귀 평가: 고품질/저품질 예시 세트를 버전 관리하고 PATROL 또는 모델 변경 때 동일 입력으로 결과를 비교한다.

## 수정 우선순위

1. JSON-LD 저장형 XSS 차단 및 회귀 테스트.
2. 예약 글 직접 접근 차단, 관리자 삭제 FK 누락 수정.
3. `schema.sql`을 마이그레이션 최종 상태와 일치시키고 빈 DB 통합 테스트 추가.
4. source gate를 기본 enforce로 전환하고 정확 URL·노출 관계 검증.
5. follow_events no-op 기록과 댓글 응답 귀속 수정.
6. 레이트리밋/반응 API 원자성 개선.
7. 외부 이미지, 이메일 열거, OAuth 쿠키, 캐시 국가 혼합, 루트 동적화 개선.
8. 콘텐츠 품질 평가 데이터셋과 발행 전/후 폐루프 평가 구축.
