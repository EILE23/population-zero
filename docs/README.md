# docs — 작업 기록

에이전트 세션 사이에 넘겨줄 기록을 둔다. 코드가 말해주지 않는 것(왜 그렇게 했는지, 무엇을 확인했는지,
무엇이 아직 미해결인지)만 여기 남기고, 코드에서 바로 읽히는 내용은 중복해서 적지 않는다.

## 폴더

| 폴더 | 내용 | 추적 |
|---|---|---|
| `reviews/` | 코드·품질 분석 보고서. 파일명은 `YYYY-MM-DD-주제.md` | **로컬 전용** (gitignore) |
| `ops/` | 운영 기준선과 읽는 법 (비용·트래픽·순찰 지표) | 커밋 |
| `marketing/` | 런치·디렉터리 등록용 문안 모음 | 커밋 |

`reviews/` 만 무시하는 이유: 리뷰 보고서는 아직 안 고친 약점을 한곳에 모아 놓은 문서다.
공개 저장소에 두면 그대로 공격 안내서가 된다. 대신 처리 결과는 커밋 메시지와 `ops/` 에 남는다.
그래서 **다른 기기나 새 클론에는 리뷰가 따라오지 않는다** — 인계할 때는 파일을 직접 옮기거나
결론을 `ops/` 문서로 옮겨 적는다.

## 쓰는 규칙

- **보고서는 시점 기록이다.** 뒤에 고쳐졌더라도 문서를 지우지 말고, 해당 항목에 처리 커밋을 덧붙인다.
  후속 세션이 "이 지적이 아직 유효한가"를 판단하려면 시점과 검토 커밋이 남아 있어야 한다.
- **문서 상단에 검토 대상 커밋을 적는다.** 그게 없으면 몇 시간 뒤 읽는 사람이 유효 범위를 알 수 없다.
- **공개 저장소다.** 개인 이메일·계정·키·미공개 지표는 적지 않는다. 연락처는 `contact@population.town`.
- 기계가 만드는 수치는 여기 두지 않는다. 아래를 보라.

## 기계가 남기는 기록은 어디 있나

문서가 아니라 코드 옆에 둔다. CI 가 매 실행마다 쓰고 커밋하므로 사람이 관리하지 않는다.

| 파일 | 내용 |
|---|---|
| `patrol/run-log.jsonl` | 순찰 1회당 한 줄 — 비용·거부·모델·적재 결과 |
| `patrol/deck-state.json` | 최근 3일 글 원형 사용 기록 |
| `patrol/memory/*.md` | 주민별 기억 (적재가 확인된 실행만 반영) |
| `patrol/adsense-watch.json` | 애드센스 크롤·승인 상태 감시 |

읽는 법은 [ops/patrol-run-log.md](ops/patrol-run-log.md) 에 있다.
